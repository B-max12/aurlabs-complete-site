# Architecture of the live v2 site

## Request flow and routes

The public custom domains terminate at the Sites/Cloudflare hosting gateway and reach a Cloudflare Worker. `build/sites-worker.ts` calls Vinext's fetch handler with the request environment. The gateway supplies trusted identity headers for ChatGPT sign-in. `app/[[...slug]]/page.tsx` validates route segments, calls `lib/server.ts` to merge D1 overrides with `lib/content.ts`, then renders `app/site.tsx`. Each dynamic request can see newly saved CMS content; saving database content does not require a code deployment. Source/style/layout edits require a rebuild/deploy.

The catch-all accepts home, products, about, journal, research, join, support, contact, privacy, terms and admin. Only products/journal/research accept a second slug segment. Unknown/deeper paths use not-found. The current 17 concrete page routes and rendered text are in `data/rendered-pages.json` and `CONTENT_AND_SEO.md`. APIs are separate route files under `app/api`.

`app/site.tsx` is the public client composition and lazy admin entry. `app/forms.tsx`, `app/visuals.tsx`, `app/lab-workbench.tsx` and `app/auri.tsx` own focused features. The many `components/ui` files are complete retained reusable wrappers; their presence does not mean each is used on a live page. Public design is primarily custom CSS and Lucide icons rather than an autogenerated component screen.

## Data and server behavior

`DB` is a real Cloudflare D1 binding, not an environment string. `content` holds JSON CMS overrides and deletion markers; settings merge into seeds and lists replace records by ID. Published/draft state affects public reads. `submissions` stores contact messages and volunteer applications as JSON plus indexed fields. `media` indexes R2 images. `administrators` stores the single owner identity, username, PBKDF2 hash and salt. `admin_unlocks` stores hashed expiring unlock tokens. `rate_limits` holds bounded attempt windows; `audit_log` records admin operations.

The latest read-only export found zero rows in **content, media and submissions**, with no truncated pages. Therefore the complete visible catalogue/editorial/team/settings content is reproduced from source and `data/public-content.json`. No claim is made that the other four tables are empty. Their private operational records are not exported. Schema and original migrations are included. The media-index read is not a complete R2 inventory; orphan objects could exist outside it.

Public forms POST to `/api/submissions`; the handler validates with Zod, checks origin, honeypot/consent, application availability, rate limits and an idempotency key, then writes to D1. **It does not send email.** Replies in the admin UI use `mailto:` and open the operator's email application. The public address is aur@Aurlabs.online. Donation links are empty and support inquiry does not charge money.

Admin API requests require a gateway-provided identity matching the stored owner plus a valid 30-minute unlock token. First enrollment additionally requires a server-only setup secret. Passwords use PBKDF2-SHA-256 with 100,000 iterations. The trusted header boundary must be replaced for any independent hosting: accepting a caller-supplied `oai-authenticated-user-id` is not authentication. The localhost mock in the vendored plugin strips these headers and operates only on loopback; it is development-only.

Media POST validates type signatures and a 5 MiB limit, stores bytes in `BUCKET` (R2), and indexes the result in D1. GET `/api/media/:key` validates the generated filename and sends an immutable public response with nosniff/CSP headers. Do not upload private records to this public image path. V2 does not have the v3 reference-aware delete or full dimension validation.

## Dynamic client features

- The hero sculpture is an included raster image tilted by pointer-driven CSS; it is not a downloadable 3D model.
- Product concept illustrations and article covers are generated by JSX/CSS/SVG in `app/visuals.tsx`. Team placeholders use initials, not missing photographs.
- The workbench changes the selected concept; the catalogue synchronizes filters/sort/page state with the URL. Product details support platform/version selection and screenshots. Clipboard controls copy links/checksums with fallbacks.
- Auri is deterministic help. It handles guide events, field help and placement, dialog search/FAQs, session preferences, minimize/reset and optional procedural Three.js rendering. It sends no prompt or form value to an AI provider.
- The live join flow has **three steps**. Draft behavior is implemented in `app/use-form-draft.ts`; the four-step review and revised opt-in behavior belong to unreleased v3. Both original and later code are available in distinct locations.
- No language switcher, i18n framework, application analytics ID, payment webhook, SMTP client, scheduled publisher or Supabase runtime is active in root v2.

## Styling, assets and external services

`app/globals.css` contains Tailwind 4 imports plus full custom responsive styles and original warm/cool accent colors. There is no separate Tailwind configuration file in production; CSS-first Tailwind uses `postcss.config.mjs`. Fonts are system Arial/Helvetica, Georgia and monospace, with no external font request. All original public assets are included. V3's Geist binaries remain inside its separate archive only.

The app has no active third-party browser analytics or external AI script in its source. Sites/Cloudflare edge access logs, Auth gateway and provider-managed resources are outside these files. Retained connector wrappers are optional infrastructure; no live Aur Labs feature invokes a user connector. Development connector bridge files are not a production business dependency.

## Handoff additions

The new Markdown files are the requested independent documentation. `ASSETS.md` lists every public asset and the separate historical archive. `FOLDER_TREE.txt` lists every exported file. `handoff/production-source-manifest.json` maps all 144 originals to their exact bytes; `handoff/production-originals` retains the three overwritten non-application files. `handoff/live-state.json` records the bounded native reads and hosting facts. `handoff/live-http.json` records the denied HTTP probes without inventing redirect behavior. `handoff/dependencies.json` records declared and resolved direct versions. `handoff/tool-environment-inventory.json` records optional tooling variables. `handoff/verification` holds fresh test/type/build logs and local initialization evidence. `handoff/wrangler.local.json` supplies a complete **local-only** D1/R2 resource configuration with the original simulator ID.

`scripts/start-local.mjs` is a complete local bootstrap; `scripts/verify-handoff.mjs` checks all original hashes. `data/production-content.json`, `data/production-media.json` and `data/production-submissions.json` are the measured empty row arrays, not synthetic production backups. `data/public-content.json` is the complete effective public content snapshot. `data/rendered-pages.json` contains SSR markup for all 17 current routes, not browser screenshots. `data/ui-text-catalog.json` inventories complete source text literals, including hidden states and technical strings. `history/aur-labs-unreleased-v6.zip` is the complete isolated later source. No handoff file is imported by the production application.

Generated dependency directories, local SQLite/R2 state, logs outside the explicit verification folder, secrets, temporary files and new build output are excluded from delivery. They are reproducible with the documented commands and are not required source files.
